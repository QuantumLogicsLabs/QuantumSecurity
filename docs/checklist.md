# Security checklist

Use this before a project's first release and again before each major one.

The automated scans cover secrets, vulnerable packages, and insecure code
patterns. This list covers what they cannot see: whether the application's own
rules about who may do what are actually enforced. That is where AI-written code
fails most often, because the code looks complete and works for the honest user.

Every item is written as something you can test. [pentest-guide.md](pentest-guide.md)
explains how.

## Access control

- [ ] Every endpoint that is not meant to be public rejects a request with no token.
- [ ] User A cannot read, change, or delete user B's records by changing an ID in the URL or body.
- [ ] A normal user cannot call admin endpoints, even by typing the URL directly.
- [ ] A user cannot raise their own role or permissions through any profile or update endpoint.
- [ ] Lists and searches return only the records the caller may see.

## Authentication

- [ ] Passwords are stored hashed with bcrypt (12 rounds) or argon2.
- [ ] Login, signup, password reset, and OTP endpoints are rate-limited.
- [ ] Login gives the same answer for an unknown user and a wrong password.
- [ ] Access tokens expire. Logging out or changing the password ends existing sessions.
- [ ] Password reset links are single-use, expire, and cannot be guessed.
- [ ] Auth cookies are `HttpOnly`, `Secure`, and `SameSite`.

## Input

- [ ] Every body, query, and URL parameter is validated on the server against a schema.
- [ ] Sending an object where a string is expected (for example `{"$ne": null}`) is rejected.
- [ ] Fields the client must not set (role, owner, price, verified) are ignored when sent.
- [ ] User content shown in a page is escaped. `<script>alert(1)</script>` appears as text.

## File uploads

- [ ] There is a size limit, and a larger file is rejected.
- [ ] Only listed file types are accepted. A renamed `.html` or `.svg` is rejected.
- [ ] Stored file names are generated by the server.
- [ ] Opening an uploaded file's URL downloads or displays it. It never runs as a page.
- [ ] Files that belong to one user cannot be fetched by another user who guesses the URL.

## Configuration

- [ ] CORS allows a fixed list of origins.
- [ ] Security headers are set (`helmet` or equivalent).
- [ ] Errors in production return a generic message, with no stack trace or query text.
- [ ] Debug mode and API documentation routes are off in production.
- [ ] The production database, admin panels, and internal services are not reachable from the internet.
- [ ] HTTPS is forced.

## Secrets and data

- [ ] No secret is in the repository or its history (the secrets scan is clean).
- [ ] Production secrets differ from development ones and live in the host's secret store.
- [ ] Logs contain no passwords, tokens, or full request bodies.
- [ ] API responses return only the fields the client needs. No password hashes, no internal flags.
- [ ] Backups exist, and a restore has been tried.

## Process

- [ ] The security workflow is enforced and required on the main branch.
- [ ] Dependabot is on.
- [ ] `SECURITY.md` tells people how to report a problem.
- [ ] Someone other than the author has run through [pentest-guide.md](pentest-guide.md).
